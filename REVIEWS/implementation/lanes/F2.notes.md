# Lane F2 notes

## LOCAL-02
- `paths::prepare_state_root` makes root + sessions/status/staging/peering private (fsutil::private_dir) and runs the tmp sweep. It is called from `resolve_state_root` in main.rs (so every command taking --state-root: watch, sync-config, status, doctor, flush/verify/reset, issues, mi, diff, resolve, clean, tray, peering), from `run_sync` (manual sync, which also private_dir's its session directory), and from `run_init` when the config path is the default.
- `persist::write_atomically` now uses a `.<name>.tmp.<random>` private_file temporary, applying the replaced file's mode (0600 when new). New `persist::write_beside` is the temp-only half; `run_availability` (enable/disable) uses it because it reads the temporary back before renaming. `run_init` uses write_atomically.
- `Config::load` warns (complain!) when the config or its directory is group/world-writable; the check is `paths::loose_write_permissions`.
- NOT done (other lanes' regions): the ancestor writer (src/session/ancestor.rs, C2) and the updater (src/update.rs, F1) still use predictable temp names and default-umask modes. So ancestor *files* are still 0644 under umask 022 — but they sit in a 0700 session directory under a 0700 sessions/ and state root now, so they are unreachable to others. The ticket's "ancestors at 0600" test is implemented as "the session directory chain is 0700". C2/F1 should adopt `fsutil::private_file` temporaries.
- `autobahn agent` (remote side) does not call prepare_state_root; its staging root belongs to A2.
- Edits outside my files: small calls in main.rs (`resolve_state_root`, `run_sync`, `run_init`, `run_availability`) and a 6-line warning in `Config::load` (config.rs, D2's file, granted by the brief).

## LOCAL-04
- `run_diff`: one `fsutil::private_tempdir_in(&state_root)` per compared plan (honours --state-root), sides written with `private_file`, named `alpha` and `beta` (was `alpha` and the host name: a host named `alpha`, or an empty one, would have collided). Removed when the guard drops, right after the diff tool exits.
- Tray "Show diff": `paths::tray_diff_file(state_root, group, host, path)` → `<state root>/tmp/diff-<blake3 of group,host,path>.diff`, written with `persist::write_atomically` (0600). A write failure is now reported instead of ignored. Hash covers group and host too, not only the path (two groups can have the same conflicting path).
- The tray feature cannot build on this Linux box (no glib/gtk), so the tray.rs edit is NOT compiled here. Integrator: please `cargo check --features tray` on macOS. The naming logic lives in paths.rs so it is tested without the feature.
- The startup sweep is wired by LOCAL-02's prepare_state_root, so old tray diff files are removed after TMP_MAX_AGE.
- The ticket's "diff succeeds when /tmp/autobahn-diff-<pid> is owned by someone else" is tested as: the child's TMPDIR is unwritable, and diff still succeeds and writes nothing there (the pid can't be predicted from a test, and a foreign owner needs root).

## LOCAL-05
- `socket_path` → `socket_path_with(state_root, runtime, temporary)`: on Linux, an absolute `$XDG_RUNTIME_DIR` gives `$XDG_RUNTIME_DIR/autobahn/<digest>.sock`; else `<temp>/autobahn-<uid>/…`, else `/tmp/autobahn-<uid>/…` as before. Only used when state_root/control.sock is over 100 bytes.
- Caveat: the CLI and the supervisor must agree on XDG_RUNTIME_DIR (as they already had to on TMPDIR) for a deep state root. A service under systemd --user and a desktop terminal both have it; a bare ssh login without pam_systemd might not.
- `bind` → `bind_at`: creates the state root's parents, then `private_dir(state_root)` (was create_dir_all), and `private_dir` on a fallback directory (refuses another uid's / a symlink with an error naming it, tightens a loose one of ours). The old code discarded the chmod's error.
- Client side: new `connect()` checks `peer_is_same_user` (existing SO_PEERCRED/getpeereid helper, E1's server-side function, called not changed) and is used by `send` and `probe`; `supervisor_is_running` checks it too. A foreign server → error in send, `Probe::Absent` in probe, not running.
- Root-only tests (`a_fallback_directory_owned_by_another_user_is_refused`, `a_client_refuses_a_server_run_by_another_user`, the latter needs python3) skip unless root; I ran them under sudo and they pass, and fail with the old code / without the peer check.
- E1 owns control.rs server side; I touched only socket_path/bind and the client connects (send, probe, supervisor_is_running), plus tests. Possible textual conflict with E1 in this file.
