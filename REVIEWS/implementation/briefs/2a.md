## Tickets: the one compatibility-epoch bump

All wire-format changes land together, in one epoch bump.

1. **`F-M-SUP-supervisor-robustness.md`, M-12 part B.** Agent-side progress counters per channel, advanced by the scan, hash, transfer and apply loops. A `MuxResponse::Progress { channel, counter }` frame, sent every few seconds only when the counter moved. Controller-side silence detection: a request with no response and no progress for 60 s fails its connection, with a death reason naming the channel, the request and how long it was silent. The same applies on the controller's local endpoint served in peering attach mode. Write the ticket's tests, including a fake agent that works slowly but reports progress, which must *not* be failed.
2. **P-13's remote half** (`TODO-SPEED.md`, "One-shot for configured and remote syncs"). Carry `one_shot` in `Initialize`, and have configured syncs pass it: `src/supervisor/mod.rs`, where endpoints are opened, currently hard-codes `one_shot: false`. Measure a configured `sync` on a converged tree before and after, and put the numbers in the commit body.
3. **Remove `Response::Scan`** (L-9 and HYG-4). Every scan answers as a delta or "unchanged", so remove the variant and its arm.
4. **Stack size for new threads.** Give the thread spawns that lane E2 added (the `autobahn-handshake` thread in `mux.rs`, and the reader and writer threads in `install::run_within`) lane B2's `crate::threads` treatment where they handle tree data. Only the thread-spawn calls change.
