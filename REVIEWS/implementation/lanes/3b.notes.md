# Lane 3b notes — F-H1 stage 2

## Design
- `AncestorStore::forget` (ancestor.rs): an ordinary Achieved record of drops, synced regardless of durability. No journal format change.
- `session::{Side, Retirement, Settlement, SettlementOutcome}` + `Session::apply_settlement` (session/mod.rs): forget first (durable), then retire (renames, a fresh scan of the side, then one removal transition). Forget-before-retire is the crash-safe order. Named `apply_settlement` because `Session::settle` already exists (burst settle).
- The fresh scan before removal is needed: local transitions validate against the endpoint's own last scan (a worker's may predate the resolution, or not exist).
- Known: a local endpoint's scan can be served from the observer's published snapshot when an inotify event hasn't arrived yet; a copy edited milliseconds before the settlement can be refused (safe direction). Unit test sleeps 200 ms for that reason.

## Control / worker
- New `ControlRequest::Resolve { id, parts }` and `Resolved { id }` (appended after `Sessions`), and `ControlResponse::Resolution` (appended at the end). The registry queues all parts or none (unknown session → error), wakes each worker, and remembers the last 64 resolutions for `Resolved`.
- Worker drains parts at the top of each loop (like verify) and applies them in `attempt_once` after connecting, before `run_cycles`. Parts survive reconnection; lost on a worker panic or a reload that replaces the session (the client then reports them pending).
- Fan-out ordering: the part that retires alpha (`last: true`) waits for every other part; skipped if another failed; spares paths another part's copy was refused at. Same ordering in the local (no supervisor) path.
- Test-only `Supervisor::cycle_hooks` for the "sent mid-cycle" test.

## run_resolve
- A destination winning now overwrites *every* other destination where it differs (the confirmation lists them all), since every session forgets the path.
- No supervisor: takes every group session's `SessionLock` before opening endpoints; builds a `Session::with_lock` from the scanned endpoints to apply each part.
- Supervisor: waits up to 120 s for parts; prints which are still pending. A *paused* session holds its part until resumed, so `resolve` waits the full 120 s there. Might be worth improving later.
- The group flush after a supervised resolve stays. Lane 3a's item 5 (flush only touched sessions) edits the same tail of run_resolve, so expect a merge conflict there.
- Removed stage 1's "winner unchanged" and strict-mode messages. Root and one-way refusals remain.
- Docs describing `resolve` (if any) may want a line about forgetting (lane 2b's area).
