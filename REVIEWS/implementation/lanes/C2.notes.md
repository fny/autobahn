# Lane C2 notes

## M-32 (checksummed journal headers)
- Records are self-describing: a v3 record starts with an 8-byte marker, so a journal can hold legacy (unmarked) records followed by checksummed ones. That happens when an upgrade's checkpoint rename lands but its directory sync fails (the journal is then not cleared), so tying the header layout to the checkpoint version alone would brick such a store.
- CHECKPOINT_VERSION raised 2 -> 3, so an older build refuses the new journal as a typed UnknownFormat (the `autobahn formats`/update path) rather than as corruption. Payload encodings are unchanged.
- This affects peering: a leader on this build pushes format-3 ancestor copies that an older peer build refuses. The integrator may want this landed with the compatibility-epoch bump (runbook wave 2a).
- Departure: an open that finds legacy records rewrites the store right away (the ticket says "the next compaction"), because quiet or journal-only sessions may never compact.
- Committed as 11332de. Mutation-checked: removing the header-digest check, the legacy "something well-formed follows" check, or the "nothing legacy after a checksummed record" rule each fails a test.

## F-L-STATE (L-16..L-19), one commit d5b90a7
- L-16: flag `journal_entry_durable`. A journal that already exists at open counts as settled, so FUSE-style filesystems don't fail every durable append.
- L-17: `checkpoint_carrying` replaces the journal with the unresolved intents (temporary file, then rename). `stored_generation` now goes through `peek` and writes nothing.
- L-18: compaction failures are logged once per run of failures, with a doubling back-off counted in records. Beyond the ticket: a failed checkpoint of an over-threshold record falls back to appending it.
- L-19: `achieved_changes` returns Result. Touched outside my region: the fold closure in session/mod.rs run_cycle, one test in session/mod.rs tests, and `.expect` in tests/spec_replay.rs and tests/spec_peering_replay.rs.
- Pre-existing, not fixed: if a large record's checkpoint rename lands and the directory sync fails, and then the fallback append ALSO fails, record() errors with the on-disk checkpoint one generation ahead of memory. Later appends at the old base would then be skipped as spent on reopen. Before this lane, the same thing happened whenever that checkpoint failed after its rename; now it needs the append to fail too.
