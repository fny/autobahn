# Lane B2 notes

## F-H4
- Departure: the ticket's one-line relist alone does NOT fix a swap whose names coincide (mv live old; mv staging live, both holding f1) — verified: the new scan test and the session test both still fail with relist only. So a marked entry that is a directory is read whole (non-incremental walk of its subtree: every entry listed+stat'd, digests reused by metadata, storage still shared). This is the ticket's "optional inode check" outcome without needing a directory inode in the tree format (Node has none; adding one is out of region + wire format).
- Cost: a marked directory costs a stat walk of its subtree. On Linux a directory is marked only by create/move/delete/attrib events on it (inotify mask), and by autobahn's own invalidate() of directory transition paths (renames by autobahn now stat-walk the renamed subtree instead of adopting it). mark("") (event on the root itself) makes that scan a full walk.
- macOS: notify uses kFSEventStreamCreateFlagFileEvents; a directory rename reports the directory paths, which reach the same marked walk; MustScanSubDirs sets need_rescan → give_up → full scan. Not tested on macOS here.
- Randomized-ops test: the observer's randomized sweep lives in src/endpoint/observer.rs (lane B1's file), so I did not add a swap op there; instead added a scan-level `directory_swaps_at_any_depth_agree_with_full_scans`. Integrator/B1 may add a swap op to the observer sweep later.
- Session test added at the end of tests/supervisor.rs (`a_swapped_directory_reaches_the_beta_with_its_new_contents`).

## LOCAL-09
- digest_file opens O_NOFOLLOW|O_NONBLOCK, fstats and requires a regular file with the lstat's dev+ino, and stops reading past lstat size + 1 MiB (DIGEST_GROWTH_ALLOWANCE). Any mismatch (ELOOP, ENXIO, NotFound at open, other type, other inode, overgrowth) records Problematic("changed during scan; it will be read again"); Problematic is always retried by the next scan, and the watcher's own event for the swap marks the path. Small size changes within the allowance keep the pre-existing behavior (digest kept with the original stat, forcing a re-read next scan).
- Test hook: thread-local BEFORE_OPEN in scan/mod.rs (cfg(test)).

## F-H25 (scanner backstop only)
- scan::exclude_state_root(path) registers a state root process-wide; every scan stats the default state root ($AUTOBAHN_HOME or ~/.autobahn) plus registered ones once, and any directory inside a root with that (dev, ino) scans as Untracked, before the ignore check (so no negation re-includes it). Identity by dev/ino, so aliases/symlinks don't matter.
- Call sites outside my region (one line each): main.rs `resolve_state_root` registers the resolved root (covers every CLI entry with --state-root); transport/mod.rs `serve_agent_with` registers the agent's state root (production agents are also covered by the default).
- Not registered: Supervisor::new(plans, state_root) used directly by library callers/tests (E1's region). Integrator/D2 may want D2's topology check to call exclude_state_root too.
- Integrator/B1 watch-out: the ChangeWatcher (local.rs watch_tree) does not know about the state root, so if a root contains the state root and it is NOT pattern-ignored (only possible when D2's refusal is bypassed), state-file writes still produce events → wakeups → scans that find nothing new. Not a correctness problem; possible busy cycling. D2's refusal (or ignore acceptance, which watch_tree honours) prevents it.
- Adoption: an incremental scan adopts an unmarked baseline child unread, so a cache from before this change that recorded the state root as a directory keeps it until that directory is marked or the next full walk (≤120 s).
- Agent-side test added in src/transport/mux.rs tests (`an_agent_never_scans_its_own_state_area`), next to `spawned_agent`.
