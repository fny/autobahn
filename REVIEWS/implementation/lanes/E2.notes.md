# Lane E2 notes

## T2-1
- Header checks live in `check_delta_header` (remote.rs), per-op bound in `apply_delta_ops`. A refused header with a baseline goes through the existing ScanFull fallback (the agent clears its pending ops on ScanFull, so no drain is needed); without a baseline it is an error on the scan.
- `transport::MAXIMUM_MESSAGE_SIZE` made `pub(crate)` (my region).
- Departure: a `Signature` carries its own block count, so `validate()` cannot bound `hashes.len()` without the base length. `validate()` now range-checks `block_size`; the new `Signature::validate_for_base(base_length)` applies the ticket's `hashes.len() <= len/bs + 1` rule. The received-signature site is `supply_*` in local.rs (lane A1), where the sender does not know the receiver's base length, so nobody calls `validate_for_base` yet. The block-size check does apply there, through `deltify`'s `validate()`.

## F-M-SUP M-12 part A
- Setup deadlines: handshake and channel open (`mux::SETUP_TIMEOUT`, 60 s; `AgentConnection::connect_within` for tests), probe and upload via `install::run_within` (upload gets 60 s + size at 128 KiB/s). A missed handshake or open fails the connection as `ConnectionFailed` (the supervisor retries once, then records "unreachable" and backs off). A missed probe or upload is wrapped as `Unreachable` by `establish_ssh`, as any install failure already was.
- Pool: slot is Empty / Connecting / Ready with a condvar; the lock is never held across establish or open. Waiters give up after 5 min (`POOL_WAIT_TIMEOUT`) with "still connecting". A failed establishment empties the slot and the next waiter tries itself, which keeps the typed error (`Unreachable`) per session.
- `ConnectTimeout` goes in with OPS-4 (next commit).
- Control client: `connect_client` does a non-blocking connect (a blocking connect to a wedged supervisor with a full listen queue never returns), 5 s client timeout on connect/read/write; `send` gives `Yield` 60 s. New `Probe::Unresponsive` variant: `is_running()` true, no progress, no mismatch message. **Integrator / D1 / E1:** `status` and the tray show nothing special for Unresponsive yet (before this change a timeout read as "a supervisor of another build"); a "not responding" line in `status`/tray output belongs in their regions. The tray needed no change: its refresh goes through `status_report` → `control::probe`.
- `supervisor_is_running` treats a connect that times out (full queue) as running.
