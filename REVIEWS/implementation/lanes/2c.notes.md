## M-46 (standing watch)
- Loop now waits until alpha holds beta's edit (≤4 cycles, ≤20 s); asserts separately some cycle scanned beta.
- The 200-run loop with only that change: 6/41 failures, all at the *earlier* assertion
  "beta's watch was standing: its scan is skipped". Cause: every `await_change` ends with beta's
  watch request (≤2 s, WATCH_REQUEST_MAX) expiring at the same moment; its "no change" answer lands
  just after the wait returns, so `standing_since()` is None until the next wait re-begins it. If alpha's
  edit is written after the quiet wait, the next wait returns on alpha before beta is re-asked, and the
  cycle rightly scans beta. Test fix: alpha's edit is written 1 s *into* the wait (thread), so beta's
  request has been renewed. Product note (not my region, src/endpoint/remote.rs): after any idle wait
  times out, the next cycle rescans beta — an efficiency gap, not a correctness one.
- Deterministic hook tests for late events / polling fallback (ticket's last sentence) are observer-side,
